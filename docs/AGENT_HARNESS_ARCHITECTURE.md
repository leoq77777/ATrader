# ATrader 投资实验架构

状态：设计定稿。日期：2026-10-27。适用于后续工程实施，不表示当前线上已经具备下述能力。

**模型拥有方法自由，harness 掌握实验规则和执行边界，人掌握投资授权。**

## 1. 投资授权与方法自由

人定义投资任务的目标、资产范围、账户、资金、风险边界、研究预算与授权有效期。降低回撤和提高超额收益是不同任务。任何新增任务或扩大范围均须来自人的授权，不能由模型自建任务获取新预算。

模型自主提出经济假设、分析方法、信号、权重、现金比例、持有周期、研究候选和实验建议。不将行业轮动、均线、趋势跟踪、固定前三名或多智能体写成架构要求。当前策略接口与持仓限制属于旧实现及现有授权，在另行实现、验证之前不会因设计变更自动放宽。

降低回撤任务必须同时定义收益保留或其他投资效用要求，避免空仓成为退化最优解；超额收益任务必须冻结主基准。基准的现金、分红、成本、再平衡和计价规则是契约的一部分。其他参考指标不能在见到结果后替代主指标。

当前只授权 Alpaca Paper，不得因研究或验收通过自动转入实盘。NVDA 等范围外既有持仓不属于本次策略资金，不纳入成绩或退出处置。

## 2. 最小实验流程

自主研究 → 固定规则回测 → 登记候选与冻结契约 → Paper 试运行 → 固定裁决 → 继续执行或可恢复退出。

研究持续进行，正在执行的策略版本及参数保持稳定。回测通过只能获得候选资格，不得覆盖 Paper 执行版本。同一资金范围内一次只执行一个版本，不要求维护大型种群、多策略分配或投票系统。档案、独立上下文和多模型是可选研究手段。

旧版本的影子对照与主基准不同。是否允许替换旧版本、需要比较什么、用何种样本和统计门槛，必须在挑战开始前固定。影子运行不提交订单，且与候选采用相同观测时间和可比成本口径。

## 3. 按任务记账，按挑战预留预算

每个投资任务拥有持久、不可由模型重置的身份和授权版本。分别记录：

- 研究请求与实验次数、token、费用、失败和中断；另有跨任务的全局费用上限。
- 正式候选挑战次数、实验契约、已预留的显著性预算及裁决。
- 数据访问、数据谱系及此前研究和选择过程。

研究尝试次数与正式 Paper 挑战次数是两个计数，不能混用。研究与正式挑战均在工作开始前登记；正式挑战在任何前向成绩被观察前原子地预留预算。崩溃、ABORT、未得结论、换数据源、换研究批次或回滚不自动退还已使用或预留的预算。

同一代码或想法换到另一个已授权任务，必须登记为新挑战并占用目标任务预算，保留相同想法的谱系和原有成绩接触历史。重新登记不使重复使用的数据变成独立证据。不得通过给同一目标改名、复制任务或换指标来刷新预算。

任务内挑战预算相互独立，但不能挑选多个任务中碰巧成功的一个，再宣称获得跨任务总体显著性。若需要这种总体验收结论，还须事先登记跨任务检验族及总预算。

显著性协议预先固定：可以对预定总挑战数 K 分配 alpha/K，或对开放次数分配满足累计和不超过总 alpha 的序列，例如 alpha/[k(k+1)]。不能无限使用 alpha/k。预算记账不保证单次检验有效，也不能追溯消除旧样本的适应性选择。

## 4. 不可事后修改的实验契约

每轮契约至少包括：

| 约定 | 必须保存的事实 |
|---|---|
| 任务与授权 | task_id、授权版本、目标、资产及账户范围 |
| 策略与谱系 | 源码及参数指纹、研究来源、同想法历史登记 |
| 资金归属 | 初始分配资金、所属持仓、外部持仓、资金流口径 |
| 对照与目标 | 主基准、可比旧版本、成功标准、失效标准 |
| 时间与统计 | 起止、交易日历、固定检查日、功效估计、挑战编号与显著性预算 |
| 数据与执行 | 决策可见数据、下单时点、订单政策、重放协议和容差 |
| 成本 | 费用与分红口径、压力滑点倍数及正下限、监管费、防重复扣费 |
| 风险与终止 | 高水位、预警及暂停线、ABORT 条件、退出与恢复规则 |
| 证据不足 | 到期默认动作、是否存在预先限定的延期与预算 |
| 信息权限 | 模型可见事实、禁用的前向成绩与市场区间、结果解封政策 |

字段缺失或未校准时不得开始自动验收，也不得用隐含默认值补出绩效门槛。登记后契约不可覆盖修改；实质变更必须结束原实验并按新挑战登记，保留原记录与预算消耗。

60 个交易日是拟定最低观察期，不是有效性证明。由目标效应、超额波动、检查方案、重复挑战预算和统计功效确定能回答的问题；所需样本过长时，契约明确 Paper 主要验证执行，绩效结论可能长期不足。

## 5. 资金归属与风险连续性

券商账户、订单及成交是经纪商事实来源；harness 记录策略所属资金、持仓、现金流和调整项。归属账本不是另一个自行撮合的 Paper account。

策略净收益 = 期末策略净资产 − 期初策略净资产 − 期间外部净流入。包含已实现、未实现盈亏、分红和费用，排除范围外持仓及无关资金流。模型滑点只在压力账本扣除，实际成交已体现的滑点不能重复扣除。

Alpaca Paper 不模拟分红，研究/绩效调整必须与原始券商余额并列保留，不能伪称券商已付息；调整不可变成额外可下单现金。模型费用和已知真实费用分别标识，未知费用不能假报为已确认的零费用。

当前约定：策略资金净资产相对高水位回撤 15% 预警、25% 暂停并启动风险退出。外部资金流须以单位化或等价方式消除对高水位的影响。版本切换不能抹去亏损、重置任务资金的风险轨迹。阈值是触发边界，不保证实际损失被限制在阈值以内。

不能识别的人工交易、资金流或核对差异使绩效不可归因，应阻止继续验收并核对，而不是猜测归属。

## 6. 模型可见信息：先实现最小边界

当前同一资金范围只运行一个候选，执行过程确定，不增加实时模型调用。第一版只要求：

1. 候选登记时冻结研究数据截止边界，研究快照不得晚于登记时刻当时已可见的最后一根完整行情，后续不得滚入该候选的 Paper 观测区间。若登记发生在收盘前，不得使用当日事后完整日线。首次启用须先检查冻结数据中是否已有被保护的 Paper 观测。
2. 研究模型不读取看板、账户、实时净值、PnL、超额表现或检验进度。仅接收必要且最少的执行/安全事实，不附带能还原成绩的资金或持仓明细。模型仅通过 harness 构造的请求参与，不直接持有生产工具或凭据。
3. 每次请求在发送前保存实际系统/用户内容、数据快照身份及截止边界；请求正文记录不得带入 API 密钥。

用户看板与确定性风控可处理完整事实；不能把它们的展示内容转发到研究上下文。实验结束不自动使成绩成为可复用的独立证据；解封后生成的候选不得再声称对该区间独立验证。

完整访问控制、间接重建检测、跨路径泄露审计，暂不建设。启用运行期持续研究、滚动新数据或带工具的模型前，先审查并补足这些机制；不得直接沿用本节的最小假设。现有冻结研究样本和请求留存只能作为基础，不代表所有隔离要求已验收。

## 7. 两类验收与固定裁决

### 执行一致性

同一版本、同一初始状态和同一时点可见快照重放，应产生一致的决策，允许预先定义的数值舍入。随后核对目标、订单、部分成交、撤单及实际持仓，解释价格和时间差异。事后修订日线不能替代当时快照。

行情、版本、时点、订单政策或成本口径不同，应先解释原因，不得用宽泛绩效波动容忍工程错误。逐单滑点、完成时延和持仓残差容差须由执行精度、时点及观测确定，不能由策略超额收益波动单独推出。

### 绩效验收

只在预定检查日按冻结规则判定。中途不临时增加绩效否决，只监控执行与风险边界；若将来需要序贯绩效停止，必须在开始前登记有效的边界和预算。

| 结果 | 含义与后续动作 |
|---|---|
| 接受 | 满足任务验收标准；替换旧版本还须通过单独登记的替换门槛 |
| 未被证伪 | 仅表示没有达到否决条件；在原契约期限与风险范围内继续，不等于接受或有权替换 |
| 绩效失败 | 有效实验触发预登记失效标准，按契约退出或交接 |
| 未得结论 | 到期证据不足，进入冻结的默认处置，不能临时延长 |
| ABORT | 执行、数据或归属问题使实验无效，暂停新增风险并核对，不计成功或绩效失败 |
| 风险终止 | 触及硬风险边界，不等待统计结论；记录独立原因，不强行给绩效标签 |

默认失败与未得结论处置：停止候选的新订单，核对和撤销所属未完成订单，退出其持仓、转现金。范围外 NVDA 不参与。契约可在开始前明确指定交接某个已接受旧版本，或明确限定延期规则与预算；否则不自动恢复旧版本、不自动转基准 ETF、不无限继续观察。市场关闭或执行不可用时，持久化待退出状态并等待可执行时机，不能假报已经持有现金。

“未得结论”是正式终态；若契约预先安排了中间检查与继续观察，那是同一既定实验的阶段，而非终态后偷偷延期。结束后的再次启动属于新挑战；重复前向数据的检验有效性需另行处理。

## 8. 可恢复退出与版本交接

顺序固定：禁止旧版本新增订单 → 识别所属未完成订单 → 撤销并核对撤单竞态及部分成交 → 确认实际现金和持仓 → 按契约生成退出或接任目标 → 提交并核对成交 → 完成处置。

订单意图先持久化再提交，使用可重试身份；重启先查询券商，不能盲目重发。所属关系未知的订单不能擅自撤销。退出本身允许多轮核对，不能以提交成功代替成交确认。

若恢复已接受版本，它必须基于当前真实资金和持仓决策，不能恢复历史余额或重置损失。执行设施故障先恢复核对能力，不盲目启动另一个策略交易。

## 9. 数据与可复现性

公开长期数据用于跨周期研究与稳健性验证，不阻塞本架构。记录数据源、版本、时间覆盖、调整方式、可见时点、资产成立时间、缺失、代理序列和许可条件。不能将 ETF 成立前的指数或代理回填称作可交易 ETF 的真实历史收益。

研究、选择与密封验证区间分离，保留每次数据访问及此前成绩接触历史。换数据源、换任务、扩大样本或新建批次不会自动产生独立证据。

归档至少包含契约、策略版本、研究 token/费用/错误、决策可见快照、订单意图、券商回报、资金归属、调整项、核对差异、裁决和退出进度。看板只读展示，不提供交易和实验控制入口。关键事实不缺失，不为设计整齐引入大型平台或微服务。

## 10. 实施顺序、工程上限与现状

0. **先冻结 Paper 执行版本。** `paper_execution_frozen` 默认 `true`，研究继续生成、评分及归档；即使达到旧回测晋升门槛，也只记录 `CANDIDATE (PAPER FROZEN)`，不替换 `strategy.py`、不新增前向执行版本，也不把候选成绩冒充执行策略成绩。缺失或非布尔值均按冻结处理。模型无权改开关；本阶段不解冻，后续必须具备正式验收交接路径后再另行审查。
1. 实验登记：授权任务身份、最小不可变契约、按任务预算、谱系、到期默认动作；同时落实第 6 节三项最小信息边界。
2. **资金归属和高水位风险退出一起做。** 先将策略资金与 NVDA 等外部持仓分离，确定资金流、高水位和费用/分红口径；随即落实 15% 预警、25% 暂停和退出。无需等待完整绩效核对框架，但风险卖出仍须用既有订单身份核对和持久化退出进度，不能盲目重试或假报平仓。
3. 成交核对：决策快照、所属订单、成交竞态、重放与差异归因。
4. 固定裁决：到期、统计预算、绩效检查、未得结论、ABORT 与风险终止的固定分支。
5. 可恢复退出：在第 2 步的风险退出基础上，统一普通试验结束、重启恢复、现金确认及旧版本交接。

前五步（1–5）每步工程投入以一周为目标、两周为硬检查点，按约 5–10 个工作日量级预算，不预支成固定工期。超过上限先停止扩展，交付已验证的最小结果、未解决问题和继续所需成本，重新评估后再投入。已运行的风控和服务不能因工程时间到期而停止。大型平台、通用实验系统和完整泄露审计不进入首轮范围。

架构提供的是实验可追溯、执行与裁决可信的条件，不保证有优势策略。长期反复“未得结论”是可接受结果，不通过降低门槛、延长观察或增加基础设施掩盖；到工程检查点还须比较研究与工程的实际价值，保留寻找优势的时间。

当前已有：Alpaca Paper 接入、确定性每日订单身份及部分核对、冻结研究样本、研究尝试/费用记录、受限策略 worker、只读看板。第 0 步以冻结开关阻止旧评分晋升影响执行，研究记录仍保留评分和成本；该保护不等于正式 Paper 验收。

当前尚缺：正式任务授权与分任务预算、完整契约、策略资金归属、实时高水位风险退出、Paper 绩效验收、第 6 节最小边界的登记集成、到期默认处置、可恢复持仓退出和版本交接。研究自身仍使用旧行业接口和评分，不在第 0 步扩大改造。

15%/25% 风险保护尚未上线；绩效阈值、逐单容差与具体任务授权仍须在启用相应闭环前校准并登记。第 0 步不修改或重置任何已有订单、持仓、现金、研究计数与密封样本。

## 11. 本次上线范围：执行与风控观察（2026-10-27）

用户已明确选择先上线执行与风控观察，不同时启用正式绩效验收。该范围优先于第 10 节的历史缺口描述：

- 当前冻结版本在同一个已授权行业研究任务下登记一次观察。契约记录账户身份、代码快照、初始策略资金/持仓、范围外持仓、研究样本及预算、60 个未来完整交易日、15%/25% 风险边界和到期转现金。注册拒绝覆盖已有记录，正式挑战及显著性预算消耗仍为零。
- 策略资金为登记时已核对的账户现金与所属行业 ETF 持仓；NVDA 仅保留并核对数量，不计入策略净值或退出。以登记时策略净资产开始高水位覆盖，不编造登记前的高水位。
- 每次交易轮询先核对登记后的账户活动、所属成交、现金及持仓，再决定是否允许普通调仓；即使休市或当天已完成调仓，也先运行风控。未知资金流、费用、公司行动、人工交易或账实差异先阻止新增交易并显示核对原因，不自行分配现金或重置高水位。第一版不自动接受外部资金流。
- 15% 预警，25% 锁定退出；风险或到期退出均持久化，先撤销并核对所属普通订单，再用固定客户订单身份卖出所属 ETF。休市等待；超时先查订单，部分成交继续核对，拒单保留风险停止并最早下一交易日重试。只有所属持仓清零且活动/现金核对通过才标记现金状态。NVDA 和未知订单不擅自处置。
- 核对故障时不盲目卖出归属不明的仓位；退出状态保留，恢复可核对状态后继续。轮询/交易中断、市场跳空或流动性问题仍可能使损失越过阈值，不能将配置阈值当作保证。
- 研究继续使用登记前的冻结样本及原有预算，记录 task_id；阻止自动更换样本或预算。每次 API 请求前保存实际消息、模型、温度和快照边界，不发送账户或观察成绩。没有引入生产工具访问。
- 普通调仓保存决策时行情、持仓、公共配置、价格及计划快照。只读看板展示观察状态、策略净资产、高水位、回撤、到期时间、核对错误和退出阶段。

### 用户授权清除旧 NVDA（2026-10-27）

用户明确要求清除旧 NVDA 持仓。该动作以附加、可审计的 `observation/nvda_cleanup.json` 登记，只授权卖出原契约中范围外的 NVDA 数量，不修改原契约。下一次正常开市后由既有轮询执行，先保存订单身份、再提交、核对实际成交；部分成交和超时均不能重复卖出，异常订单等待核对。

此为人的定向资产清理授权，不是模型的交易权限扩展。实际卖出所得重建为外部现金储备，从策略净值、现金和下单资金基数中排除；原始券商总余额仍会包含这笔现金。旧成交历史保留，不伪造删除历史。清理未确认完成时不新增策略订单；既有策略高水位与资金起点不重置。原“NVDA 不参与策略退出”仍有效，此次出售是独立的人为授权。
